Diagnostic de la base de données

Cette page interroge la vraie base et répond à une seule question : quelles colonnes existent réellement, parmi celles que le code du gestionnaire de tournoi utilise. Puis elle écrit toute seule le SQL qui crée ce qui manque.

Elle ne modifie rien. Aucun INSERT, aucun UPDATE, aucun DELETE : uniquement des SELECT … LIMIT 0. Tu peux la lancer autant de fois que tu veux, même pendant une compétition.

Pourquoi cette page existe

Quand une page écrit dans une colonne qui n'existe pas, PostgreSQL répond 42703 et refuse la ligne entière, pas seulement la colonne fautive. Et jusqu'ici, la plupart de ces échecs finissaient dans un console.warn() : la page affichait quand même « enregistré ».

C'est l'origine de « la formation de départ n'est plus là », de « tout est mélangé » et des relevés qui ne se retiennent pas. Tant qu'on ne sait pas ce que la base contient vraiment, on répare à l'aveugle.

Le SQL qui répare

À coller dans Supabase → SQL Editor → Run, puis relancer l'analyse : tout doit passer au vert. Le script est non destructif — uniquement CREATE TABLE IF NOT EXISTS et ADD COLUMN IF NOT EXISTS.
